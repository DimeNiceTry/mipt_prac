# Домашняя работа 1: Linux

Три Bash-скрипта для сравнения веток Git, мониторинга системы и поиска по логам.

## Требования

Linux, Bash 4+ и Git. Также нужны стандартные утилиты `awk`, `grep`, `df`,
`date`, `mktemp`, `nohup` и `flock` (пакет `util-linux`). Для Windows подойдёт
Ubuntu в WSL. Монитор использует Linux-файлы `/proc`.

Все команды ниже выполняются из каталога репозитория. Скрипты создают отчёты
в текущем каталоге. Повторный запуск с теми же параметрами перезаписывает
TXT-отчёты, а монитор дописывает строки в CSV. Отчёты и служебные файлы
монитора исключены из Git.

## 1. Сравнение веток

```bash
bash branch_diff.sh https://github.com/example/project.git main develop
```

Аргументы: адрес репозитория, первая ветка, вторая ветка. Для приватного
репозитория доступ Git должен быть настроен заранее.

Результат: `diff_report_main_vs_develop.txt`. В отчёте указаны репозиторий,
ветки, дата, список файлов и статистика. Изменения рассматриваются в
направлении от первой ветки ко второй:

- `A` — файл добавлен во второй ветке;
- `D` — файл удалён во второй ветке;
- `M` — файл изменён;
- остальные статусы, например `T` при изменении типа файла, считаются отдельно.

Переименование учитывается как удаление старого файла и добавление нового.
Сравниваются итоговые состояния веток, а не история коммитов.
Слеши в названиях веток заменяются на `_` только в имени отчёта:
`feature/test` превращается в `feature_test`.

Репозиторий загружается во временный каталог, который удаляется при завершении.
Рабочая копия пользователя не изменяется. Допускается и путь к локальному
репозиторию вместо URL.

## 2. Мониторинг системы

```bash
bash system_monitor.sh START
bash system_monitor.sh STATUS
bash system_monitor.sh STOP
```

Скрипт принимает одну из трёх команд. `START` запускает фоновый процесс
и выводит его PID. Повторный `START` сообщает PID уже работающего экземпляра.
`STATUS` показывает, запущен ли монитор. `STOP` завершает процесс.

Первый замер занимает около секунды и выполняется сразу после запуска.
Следующие замеры начинаются каждые 600 секунд. Файл
`system_report_YYYY-MM-DD.csv` имеет заголовок:

```text
timestamp;all_memory;free_memory;%memory_used;%cpu_used;%disk_used;load_average_1m
```

Поля строки:

| Поле | Содержание |
| --- | --- |
| `timestamp` | Местное время в формате `YYYY-MM-DD HH:MM:SS` |
| `all_memory` | Общая оперативная память в MiB, по `MemTotal` |
| `free_memory` | Свободная оперативная память в MiB, по `MemFree` |
| `%memory_used` | `(MemTotal - MemFree) / MemTotal * 100`, включая кеши |
| `%cpu_used` | Общая загрузка всех ядер за секундный интервал по `/proc/stat` |
| `%disk_used` | Занятое место на разделе `/`, в процентах, по `df` |
| `load_average_1m` | Средняя нагрузка за минуту по `/proc/loadavg` |

Десятичный разделитель — точка. На каждую дату создаётся отдельный CSV;
заголовок записывается один раз. После перезапуска сбор продолжается в том же
файле, если дата не изменилась. Отчёты остаются в каталоге, из которого был
выполнен `START`, даже если `STATUS` или `STOP` вызваны из другого каталога.

Служебные файлы находятся в `.system_monitor/` рядом со скриптом: PID,
блокировки и журнал `monitor.log`. Этот каталог должен быть доступен для
записи. Блокировка `flock` предотвращает запуск дубликатов, в том числе при
одновременных командах `START`. При проверке PID учитывается время старта
процесса, чтобы не остановить другой процесс с повторно использованным PID.
Команда `--run` используется внутри скрипта для фонового процесса.

## 3. Поиск по логам

```bash
bash log_search.sh /var/log/app.log ERROR
```

Аргументы: путь к лог-файлу и непустое ключевое слово. Поиск выполняется по
обычному тексту с учётом регистра. Для фразы с пробелами нужны кавычки:

```bash
bash log_search.sh "app server.log" "connection failed"
```

В текущем каталоге создаются два файла:

- `app.log.matches.txt` — все строки с ключевым словом;
- `app.log.count.txt` — имя исходного файла, ключевое слово и количество строк.

Количество также выводится в терминал. Строка с несколькими вхождениями
считается один раз. Если совпадений нет, файл со строками будет пустым,
а количество равно нулю. Исходный лог не изменяется.

## Коды завершения

`0` — успешное выполнение, включая отсутствие различий или совпадений;
`1` — ошибка выполнения; `2` — неверные аргументы.
